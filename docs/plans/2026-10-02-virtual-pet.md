# Virtual pet implementation

Implement the supplied v1.1 system and design handoffs in the existing React/Vite,
Express and MongoDB companion flow. Keep authenticated shared-family ownership,
operation receipts, identity, memories, and legacy artwork. No new dependencies.

1. Add shared growth contracts and a versioned Lv1–10 catalog. Author discrete
   tail/crest, paw and wing/horn/gill steps; final pools retain their precursors.
2. Add pure server progression, care evidence, reward-day limits and HMAC streams.
   Persist plans, render snapshots, outcomes and audit within the existing receipt
   transaction. Presentation acknowledgment changes no gameplay state.
3. Add explicit legacy migration without retrospective random outcomes. Preserve
   earned level and XP, including levels above the new live cap. New pets receive
   tutorial once. Use chronological age and 12-hour assisted rest for v4 pets.
4. Integrate care, completed activities, prompt choices, chat fallback and privacy
   into the existing API. Check family ownership before reads and writes. Keep
   secrets and private RNG audits out of public snapshots.
5. Render modular SVG anatomy, growth hints, before/after history, reveal and
   capability activities in the existing companion panel. Translate added copy.
6. Run focused Node tests, root tests, typecheck and build. Record manual visual
   and configured-database checks that cannot be verified locally.

Level 30 is a design target. Do not enable Lv11–30 with missing authored content.
Existing species and multiple companions remain compatible rather than deleting
the user's existing family. Catalog art needs perceptual review before release.

Validation: `npm run typecheck`, `npm test`, `npm run build`.
